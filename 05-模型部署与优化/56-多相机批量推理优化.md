# 第 56 题：如何优化多相机输入的批量推理效率

## 题目

如何优化多相机输入的批量推理效率？

---

## 一、多相机推理的特点

多路相机（如 6～8 路）需**同时或近同时**出结果；单路单 batch 调用会**GPU 利用率低、延迟叠加**；需要**批处理、流水与并发**提升吞吐与延迟。

---

## 二、优化思路

**1. 批处理（Batching）**  
- 把**多路图像拼成一个大 batch**（如 6 路×1 = batch 6），一次前向，充分利用 GPU 并行。  
- 注意：各路分辨率一致或先 resize 到统一尺寸；batch 过大可能延迟与显存上升，需在**延迟与吞吐**间折中（如 batch=4～8）。

**2. 多流（Multi-Stream）**  
- 使用 **CUDA stream**：多路图像**并行预处理与拷贝**，再在**同一或不同 stream**上推理，overlap 数据准备与计算。  
- 多 stream 可并行多 batch，提高吞吐；注意与 batching 组合（如每 stream 一个 batch）。

**3. 预处理与拷贝**  
- **CPU 预处理**（解码、resize、归一化）与 **GPU 拷贝** 尽量与上一次推理 **overlap**（双缓冲、异步拷贝）。  
- 能用 **GPU 预处理**（DALI、CUDA kernel）则减少 CPU→GPU 与同步点。

**4. 模型与引擎**  
- **TensorRT/ONNX Runtime** 对**固定 batch** 优化更好；多相机固定路数时可设 **opt batch = 路数**。  
- **动态 batch**：若路数不固定，用 min/opt/max profile，避免频繁重建引擎。

**5. 流水线**  
- **Pipeline**：采集 → 预处理 → 推理 → 后处理 分阶段，各阶段**异步队列 + 多线程/多 stream**，使“下一帧预处理”与“当前帧推理”并行。  
- 端到端延迟 = 单帧各阶段之和，吞吐 = 瓶颈阶段的 throughput。

**6. 多相机共享 backbone**  
- 若各相机**独立网络**，可改为**共享 backbone、多路 head** 或**大 batch 多路输入**，减少重复计算与 kernel launch。

---

## 三、小结与面试要点

**小结**：多相机优化=批处理（多路拼 batch）+ 多 stream + 预处理与推理 overlap + 固定/动态 batch profile + 流水线；目标=高吞吐、可控延迟。

**面试要点**：能说清 batching、stream、overlap、流水线；固定路数时 opt batch 设路数；端到端延迟与吞吐的权衡。

---

## 记忆要点

1. **Batch**：多路拼成一大 batch，一次前向。  
2. **Stream**：多 stream 并行，overlap 拷贝与计算。  
3. **流水**：预处理与推理重叠，双缓冲/异步。  
4. 固定路数时引擎 opt batch=路数；多路共享 backbone 可省算力。
