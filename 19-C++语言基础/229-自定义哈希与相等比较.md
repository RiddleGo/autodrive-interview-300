# 第 229 题：自定义哈希与相等比较

## 题目

如何让自定义类型作为 std::unordered_map 的 key？需要提供什么？哈希函数与相等比较有何要求？

---

## 一、unordered_map 对 key 的要求

**key 类型**：必须支持两类操作—**哈希**（可得到 size_t）与**相等比较**（可判断两 key 是否相等）。  
**默认**：内置类型与 std::string 等已有特化；自定义类型需**自己提供**哈希函数与相等比较，或特化 **std::hash** 与 **operator==**。

---

## 二、方式一：特化 std::hash 与 operator==

**相等**：为类型定义 **operator==**，保证相等键比较一致。  
**哈希**：在 **namespace std** 里 **template<> struct hash<MyType>**，实现 **size_t operator()(const MyType&) const**；需满足：**相等则哈希必相等**，尽量让不同对象哈希分布均匀以减少冲突。  
**使用**：`unordered_map<MyType, Value>` 即可，无需额外模板参数。

---

## 三、方式二：自定义函数对象并传入模板

**定义**：写两个**函数对象**（或 lambda），一个做 **hash**（接受 key 返回 size_t），一个做 **equal_to**（接受两个 key 返回 bool）。  
**使用**：`unordered_map<MyType, Value, MyHash, MyEqual>`；当不能或不想特化 std::hash 时使用（如第三方类型、多种哈希策略）。  
**注意**：哈希与相等必须**一致**—若 a == b 则 hash(a)==hash(b)；否则会破坏 unordered_map 语义。

面试可答：自定义类型作 key 需可哈希与可相等比较；可特化 std::hash 和 operator==，或传入 Hash 与 Equal 模板参数；要求相等则哈希值相同。

---

## 小结与面试要点

**小结**：unordered_map 的 key 需哈希与相等；可特化 std::hash 与 operator==，或提供 Hash/Equal 仿函数；相等⇒哈希相等。

**面试要点**：能写出特化 hash 与 == 或传入自定义函子的方式，并说明一致性要求。

---

## 记忆要点

1. **需求**：key 支持 **hash** 与 **相等比较**。  
2. **方式**：特化 **std::hash<T>** + **operator==**；或 **unordered_map<K,V,Hash,Equal)**。  
3. **一致性**：若 a==b 则 hash(a)==hash(b)。
