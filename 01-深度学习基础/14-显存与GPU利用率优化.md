# 第 14 题：显存占用高但 GPU 利用率低的排查与优化

## 题目

训练时显存占用高但 GPU 利用率低，可能原因及优化方案？

---

## 一、现象与含义

- **显存高**：模型参数、梯度、激活、优化器状态等占用了大量 VRAM。
- **利用率低**：GPU 算力（SM 占用率、算力曲线）长时间处于低位，说明**算力没有被喂饱**，存在瓶颈在 CPU 或数据或调度上，而不是“算不过来”。

常见组合：**显存快满了，但 GPU 大部分时间在等**，训练慢且显存浪费。

---

## 二、可能原因

**1. 数据加载成为瓶颈（最常见）**
- DataLoader 的 worker 少、磁盘慢、预处理重（解码、增强、IO），导致 **GPU 算完当前 batch 后要等下一个 batch**，利用率周期性掉下去。
- 表现：nvidia-smi 里 GPU-Util 波动大，有时接近 0；或 CPU 某个核 100%、GPU 不满。

**2. Batch 太小**
- Batch 小则单次前向与反向的计算量小，GPU 一次算得很快，然后等下一个 batch，**无法把 GPU 填满**，利用率低；同时小 batch 有时反而因 overhead、通信等导致显存/时间比不优。

**3. 模型或 loss 里存在同步点**
- 如多卡训练里过多的 all-reduce、同步 BN、或 loss 里依赖全局统计（如需要全 batch 的统计量），会导致 GPU 频繁等待通信或 CPU，利用率被拉低。

**4. 显存占用来源**
- 模型参数、梯度、优化器状态（如 Adam 两份动量）、**激活值**（为反向传播保存的中间结果）；大 batch、长序列、大模型都会推高显存。
- 若同时用了大 batch 为了“占满显存”，但数据又喂不饱，就会“显存高、利用率低”。

**5. 图/算子过小或 kernel 启动开销大**
- 单次前向/反向的算子很小、很多，kernel 启动与调度开销占比大，GPU 实际算的时间比例低。

---

## 三、优化方案

**数据侧**：
- **增加 DataLoader workers**（如 `num_workers=4～8`），并配合 `pin_memory=True`，减少 GPU 等数据的时间。
- **预处理与 IO 优化**：把解码、重增强放到 GPU（如 DALI）、或提前做轻量预处理、用 SSD/更快的存储、预取（prefetch）。
- **保证数据管线不空**：适当增大 `prefetch_factor`，让下一批数据提前准备好。

**Batch 与模型**：
- 在**显存允许**下适当**增大 batch size**，让单次计算量变大，GPU 一次算更久、利用率上升；若显存不够，用**梯度累积**模拟大 batch。
- **混合精度（AMP）**：用 FP16/BF16 降低显存与带宽，同样显存下可开更大 batch，提高利用率。
- **梯度检查点（Gradient Checkpointing）**：用时间换显存，少存激活多算一次，从而在显存不变下可开更大 batch。

**通信与同步**：
- 多卡时减少不必要的同步；用异步 all-reduce 或 overlap 通信与计算；能不用同步 BN 则用其他归一化。

**算子与实现**：
- 尽量用融合算子、大 kernel，减少小 kernel 启动次数；使用成熟框架（PyTorch、CUDA 库）的优化实现。

---

## 四、排查顺序建议

1. 看 **GPU-Util** 与 **CPU 使用率**：若 CPU 某核满、GPU 周期性空，先加 workers、优化数据。
2. 看 **batch size**：若很小，在显存允许下增大或梯度累积。
3. 看 **多卡**：若多卡且 Util 低，查同步与通信。
4. 看 **显存**：若已接近占满且无法再开大 batch，用混合精度、梯度检查点、或减小模型/序列。

---

## 五、小结与面试要点

**小结**：显存高、利用率低多为“数据喂不饱 GPU”或 batch 过小；优化方向是加 workers、优化 IO 与预处理、适当增大 batch、混合精度与梯度检查点、减少同步。

**面试要点**：

- 原因：数据瓶颈、batch 小、同步多、算子过碎。
- 数据：增加 num_workers、pin_memory、预取、GPU 预处理（DALI）。
- 算力：增大 batch、梯度累积、AMP、梯度检查点。
- 排查：先看 GPU-Util 与 CPU，再看 batch 与多卡同步。

---

## 记忆要点

1. **显存高、利用率低**：多数是数据或 batch 问题，GPU 在等。
2. **数据**：num_workers、pin_memory、预取、IO/解码加速。
3. **算力**：batch 尽量大（或梯度累积）、AMP、checkpointing。
4. 排查：GPU-Util vs CPU → 数据；batch 大小 → 算力；多卡 → 同步。
