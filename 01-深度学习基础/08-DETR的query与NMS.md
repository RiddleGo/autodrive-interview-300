# 第 8 题：DETR 中 query 的作用与为何能去掉 NMS

## 题目

解释 DETR 中 query 的作用，为什么能去掉 NMS？

---

## 一、DETR 的总体思路

**DETR（DEtection TRansformer）** 把目标检测做成**集合预测**：固定数目的 **object queries**（如 100 个）经过 Transformer 解码器与编码器输出的图像特征交互，每个 query 对应一个预测框 + 类别；通过**二分图匹配（匈牙利算法）**与 GT 做一对一匹配，用匹配结果算 loss，推理时直接输出 top 个预测，**无需 NMS**。

---

## 二、Query 是什么、起什么作用？

- **Query**：一组可学习的**向量**（如 100 个，维度与 decoder 隐藏层一致），作为 Transformer **解码器**的“查询”。每个 query 可以理解为“一个物体槽位”或“一个检测假设”。
- **作用**：
  1. **与编码器输出交互**：在 decoder 里，query 作为 Q，编码器输出的图像特征作为 K、V，做 cross-attention，从而让每个 query 从整图里“抽取”与一个物体相关的信息。
  2. **自注意力**：query 之间做 self-attention，让不同 query 分工、避免重复预测同一物体。
  3. **输出**：每个 query 对应一个预测：类别（含背景类） + 边界框（通常 4 维或更多），因此**预测数量固定**（如 100），且与图像内容无关。

所以 query 既是“检测槽位”，也是解码器里“问图：我负责的那个物体在哪、是什么”的查询向量；通过训练，不同 query 学会关注不同位置、不同物体。

---

## 三、为什么能去掉 NMS？

**传统检测器**：在网格或 anchor 上做密集预测，同一物体会被多个 anchor/位置预测，所以需要 NMS 按置信度与 IoU 去重，保留一个。

**DETR**：
- **集合预测 + 一对一匹配**：训练时用匈牙利算法把 100 个预测与 GT 做最优一对一匹配（匹配代价含分类与框），每个 GT 只匹配一个 query，其余 query 预测背景；loss 只对匹配上的 query 算。
- 这样训练**显式约束**“一个物体只由一个 query 负责”，query 之间通过 self-attention 已经分工，不会出现“多个 query 抢同一个物体”的冗余。
- **推理**：直接输出 100 个预测，按置信度过滤背景、取 top-K 即可，**没有同一物体的多个重叠框**，因此不需要 NMS。

简言之：NMS 解决的是“一物多框”；DETR 通过固定 query 数 + 一对一匹配 + query 间 self-attention，从设计上就做到“一物一 query”，所以不需要 NMS。

---

## 四、小结与面试要点

**小结**：Query 是可学习的解码器输入，每个对应一个检测槽位，通过 cross-attention 从图像取特征、通过 self-attention 分工；训练用匈牙利匹配做集合预测，推理时输出固定数目预测且无重复框，故无需 NMS。

**面试要点**：

- Query 作用：解码器“查询”，与编码器特征做 cross-attention，彼此做 self-attention；每个 query 输出一个框+类别。
- 去 NMS 原因：集合预测 + 一对一匹配，一个物体只匹配一个 query，设计上无重复框。
- 对比：传统密集预测一物多框需 NMS；DETR 一物一 query 不需 NMS。

---

## 记忆要点

1. **Query**：可学习向量，解码器输入，每 query 一个框+类。
2. **Cross-attention**：query 从图像特征里取信息；**Self-attention**：query 间分工。
3. **一对一匹配**：匈牙利算法，每个 GT 只对一个 query 算 loss。
4. **无 NMS**：一物一 query，无重复框。
