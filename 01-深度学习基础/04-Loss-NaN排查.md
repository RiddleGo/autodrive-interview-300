# 第 4 题：训练时 Loss 出现 NaN 的排查与解决

## 题目

如何解决训练时 loss 出现 NaN 的问题？从模型和数据角度分别阐述。

---

## 一、NaN 的常见来源

- **数值溢出**：exp、log 等产生 inf，后续运算得到 NaN。
- **除零**：分母为 0 或极小（如 BN 中 $\sigma^2=0$）。
- **梯度爆炸**：梯度极大，更新后参数变成 inf/NaN。
- **学习率过大**：一步更新跨度过大，参数飞出有效范围。
- **标签或输入异常**：含 NaN/inf、标签越界（如负的类别 id）、log(0) 等。

面试常问：“遇到 NaN 先查什么？”——先看是**第一次就 NaN**（多为数据/初始化/loss 定义）还是**训一段时间后 NaN**（多为梯度爆炸、学习率、不稳定层）。

---

## 二、从数据角度

1. **检查输入与标签**
   - 输入是否含 NaN/inf：`torch.isnan(x).any()`、`torch.isinf(x).any()`。
   - 归一化是否合理：像素是否已归一化到合理范围（如 0–1 或标准化后均值 0、方差 1）。
   - 标签是否合法：分类的类别 id 是否在 [0, num_classes-1]；分割的 mask 是否在 [0, num_classes-1]；回归标签是否过大或含异常值。

2. **检查 Loss 相关**
   - 交叉熵：类别数是否与 logits 维一致；是否有类别无样本导致 log(0)。
   - 回归/Smooth L1：目标值是否过大或存在异常离群点。
   - 自定义 loss：是否有 log、sqrt、除等，在边界处是否会产生 0/负数。

3. **数据加载**
   - DataLoader 的 collate 是否可能产生空 tensor 或异常 shape。
   - 多进程加载时是否有共享内存/随机种子问题导致极少见的坏 batch。

---

## 三、从模型角度

1. **初始化**
   - 权重过大易在前几轮就溢出；过小可能导致梯度消失后再爆炸。常用 Xavier/Kaiming 初始化，与激活函数匹配。
   - 偏置、BN 的 $\gamma/\beta$ 初始化要合理（如 $\gamma=1,\beta=0$）。

2. **网络与激活**
   - 层数很深时考虑梯度裁剪、更稳的归一化（LN/BN）、残差连接。
   - 避免在自定义模块中产生极大值再送入 exp/log（如 softmax 前做减最大值、log 前 clamp）。

3. **学习率与优化**
   - 学习率过大是 NaN 的常见原因：先减小 1–2 个数量级或使用 warmup。
   - 使用梯度裁剪（如 `clip_grad_norm_`），防止单步更新过大。

4. **特殊层**
   - BN：batch 很小时方差估计不稳定；可考虑 GroupNorm/LayerNorm 或增大 batch。
   - 除法/开根：分母或根号内加小常数 $\epsilon$，并避免在反向时出现 0。

---

## 四、排查顺序（建议）

1. 固定 batch、关闭增强，检查**第一个 batch** 的 loss 是否就 NaN → 数据或 loss 定义。
2. 若前若干 step 正常、后面 NaN → 梯度爆炸或学习率，加**梯度裁剪**、**降学习率**。
3. 检查**单层**：逐层打印中间激活与梯度，定位最先出现 inf/NaN 的层。
4. 检查 **loss 定义**：边界情况、log(0)、除零、标签范围。

---

## 五、小结与面试要点

**小结**：NaN 主要来自数值溢出、除零、梯度爆炸、学习率过大、数据/标签异常。从数据侧查输入与标签合法性、loss 定义边界；从模型侧查初始化、学习率、梯度裁剪与易不稳定层（BN、自定义运算）。

**面试要点**：

- 数据：输入/标签含 NaN/inf、标签越界、loss 中 log(0) 或除零。
- 模型：初始化、学习率过大、梯度爆炸、BN 小 batch、自定义层数值不稳定。
- 通用手段：梯度裁剪、降学习率、warmup、检查中间激活定位层。

---

## 记忆要点

1. 先区分：一开始就 NaN（数据/初始化/loss）vs 训练中段 NaN（梯度/学习率）。
2. 数据：输入与标签范围、loss 公式在边界是否安全。
3. 模型：初始化、学习率、梯度裁剪、BN 与含 log/除法的层。
4. 排查：单 batch 复现、逐层看激活与梯度、加 clip 与 $\epsilon$。
